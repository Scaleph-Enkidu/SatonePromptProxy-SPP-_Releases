## 先确认自己愿意支付 API 费用

当前 AIChat + SPP 教程使用 **OpenAI API** 生成回答，推荐模型 ID 为 **`gpt-6-luna`**。玩家需要自己的 API Key、可用的 API 计费账户和联网环境。只有游戏、插件文件或 ChatGPT 网页账号，都不能替代这项配置。本教程目前没有经过验证的纯离线主聊天模型安装路线。

API 用量单独计费，购买游戏或 ChatGPT Plus/Pro 订阅不会自动给这个 Mod 提供 API 额度。请在 [OpenAI Platform](https://platform.openai.com/) 查看账户条件，在 [API 计费页](https://platform.openai.com/settings/organization/billing/overview)开通计费或按页面要求购买额度，在 [API Key 页面](https://platform.openai.com/api-keys)创建自己的密钥。支付方式、支持地区、模型权限与账户额度以 OpenAI 页面为准；不要向作者购买或索要共用 Key。

SPP 使用 Responses API 及 Conversations/items 管理对话。不能只看到第三方接口写着“OpenAI 兼容”，就假定其支持本插件所需的全部功能。

## 单价依据

核查日期：2026-09-26。下表使用 **GPT-6 Luna、Standard、短上下文** 的美元单价；不使用 Batch/Flex 折扣、Fast mode 加价或区域处理加价。来源：[官方模型页](https://developers.openai.com/api/docs/models/gpt-6-luna)、[官方价格页](https://developers.openai.com/api/docs/pricing)。

| 计费项目 | 每 1,000,000 token 的价格 |
|---|---:|
| 普通未缓存输入 | $0.10 |
| 缓存命中的输入 | $0.01 |
| 写入缓存的输入 | $0.125 |
| 输出，包含计费的推理 token | $0.50 |

原模型页的字段与数值为：“Input $0.10”“Cached input $0.01”“Cache writes $0.125”“Output $0.50”，单位为每百万 token。

缓存写入价不是在普通输入价上再加一遍；同一部分输入按相应类别计算一次。依据：[缓存文档](https://developers.openai.com/api/docs/guides/prompt-caching)原文：

> “Cache-write pricing is not an additive fee”

推理过程可能没有显示给玩家，但仍收费。依据：[推理文档](https://developers.openai.com/api/docs/guides/reasoning)原文：

> “are billed as output tokens”

## 为什么不能说“一句话固定几分钱”

本页把“玩家提交一条消息，聪音回复一次”记为 **1 轮**。一轮回复分成几句语音，仍算一轮；API 按 token 收费，不按玩家说了几句收费。token 是模型处理文字的计量单位，不等于汉字数或句子数。

一轮可能产生主聊天、好感更新、阶段性关系校准、记忆整理或格式修复等多个 API 请求。当前默认好感更新间隔为每轮一次，关系校准间隔为 20 轮；实际是否执行还取决于队列与对话状态。主聊天输入还包括人格、规则、记忆、近期对话和当前问题。不能只数玩家新发的十几个字，也不能只计算屏幕上显示的回答。

SPP 5.8.23 用主聊天返回的 **总输入达到 32,000 token** 作为记忆整理触发条件，并粗估保留最近约 12,000 token 原文。这不是每轮的固定消耗、价格上限或所有后台请求的合计上限。

## 每天聊 100 轮，大约花多少

以下是**预算演算，不是该模组的实测均值或最高费用保证**。把当天主聊天与所有辅助请求的用量加总，再除以对话轮数。为避免漏算写入缓存的费用，示例把未命中的输入全部按 $0.125 的写入价计算；实际按普通输入价计费的部分会更低。

三个情形都假设全部请求使用 `gpt-6-luna`；输出数已包含可见回答和推理。人民币统一按 **$1 = ¥7 的演算汇率**换算，不代表实时汇率，未包括税费、换汇手续费、电费或其他服务收费。

| 演算情形 | 每轮摊入的总输入 | 其中缓存命中 / 写入 | 每轮摊入的总输出 | 每轮美元费用 |
|---|---:|---:|---:|---:|
| A：90% 输入命中缓存 | 30,000 | 27,000 / 3,000 | 1,000 | $0.001145 |
| B：无缓存命中 | 30,000 | 0 / 30,000 | 1,000 | $0.004250 |
| C：更多上下文与输出，无缓存命中 | 50,000 | 0 / 50,000 | 4,000 | $0.008250 |

A、B 的 30,000 是一个假设，例如主聊天 24,000 加上摊入的辅助请求 6,000；不是源码保证。C 的 50,000 同样是多个请求的每轮合计，不等于单次主聊天超过阈值后就停止整理。90% 缓存命中也不保证：首轮、间隔较久、改人格、改关系状态或整理记忆后，命中情况可能改变。

| 你想知道什么 | A：90% 命中 | B：无命中 | C：更多输入和输出 |
|---|---:|---:|---:|
| 100 轮，按每天 100 轮就是 1 天 | $0.1145，约 ¥0.80 | $0.425，约 ¥2.98 | $0.825，约 ¥5.78 |
| 1,000 轮，按每天 100 轮就是 10 天 | $1.145，约 ¥8.02 | $4.25，约 ¥29.75 | $8.25，约 ¥57.75 |
| 3,000 轮，按每天 100 轮就是 30 天 | $3.435，约 ¥24.05 | $12.75，约 ¥89.25 | $24.75，约 ¥173.25 |
| 假设已有 $5 可用余额，约能聊多少轮 | 4,366 轮 | 1,176 轮 | 606 轮 |
| 上述 $5 按每天 100 轮，约能用多久 | 43.7 天 | 11.8 天 | 6.1 天 |

$5 只用于展示“余额 ÷ 消耗”的关系，不是最低充值额、套餐或余额有效期承诺。较长的推理、重试和频繁整理会提高费用，实际花费可能超过表格。这里列出的 ¥0.80–5.78 的示例区间也不应当被理解为所有玩家的固定日费。

复算公式：

```text
单个请求费用（美元）=
  (普通输入 × 0.10 + 缓存命中输入 × 0.01
   + 写入缓存输入 × 0.125 + 输出 × 0.50) ÷ 1,000,000

每轮平均费用 = 当天所有相关请求费用之和 ÷ 当天对话轮数
可用天数 = 可用美元余额 ÷ (每轮平均费用 × 每天对话轮数)
```

普通输入、命中输入和写入输入是三部分，不要再把总输入额外加一次。推理 token 已包含在 API 输出计数中时，也不要再加一次。

## 以实际用量校准预算

先用少量对话观察 [OpenAI 用量页](https://platform.openai.com/usage)与[计费页](https://platform.openai.com/settings/organization/billing/overview)，再根据自己的真实数据估算。可按项目/API Key 区分这个 Mod 的调用，并设置账户提供的费用提醒或支出上限；两者作用不同，具体按 [OpenAI 支出控制文档](https://developers.openai.com/api/docs/guides/spend-limits)操作。

**SPP 5.8.23 的默认 `pricing` 只有旧模型条目，没有 `gpt-6-luna`。** 源码在查不到模型单价时返回费用未知，累计估算可能漏计；看到 0 或未知不能认为没有花钱。即使有旧条目，也不能认为旧单价仍有效。

若需要 SPP 面板估算当前推荐模型，可退出 SPP，在自己的 `config.json` 的 **`pricing` 对象内部新增**以下条目。保留其他键，注意 JSON 逗号；这不是完整配置，也不需要改动下载的原 ZIP：

```json
"gpt-6-luna": {
  "input_per_million": 0.10,
  "cached_input_per_million": 0.01,
  "cache_write_per_million": 0.125,
  "output_per_million": 0.50,
  "long_context_threshold": 272000,
  "long_input_multiplier": 2,
  "long_output_multiplier": 1.5
}
```

重新启动 SPP 后，这只影响本地估算，不会改变 OpenAI 的实际扣费，也不会追回补算此前漏记的费用。价格表按返回的模型 ID 精确匹配；如果服务返回不同 ID，仍需匹配那个 ID。最终以 OpenAI 账单为准。GPT-SoVITS 和 Fun-ASR 按本教程在本机运行，它们的本地合成与识别本身不调用 OpenAI 收费的语音接口。
