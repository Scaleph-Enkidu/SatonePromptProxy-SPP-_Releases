# 运行开销与硬件边界

[返回首页](../README.md) · [四阶段安装](INSTALL.zh-CN.md) · [语音设置](VOICE_SETUP.zh-CN.md)

适用配对：**AIChat 1.17.1 + SPP 5.9.1**，更新日期 **2026-10-01**。原版本的用户实机反馈与本版自动化验证分别记录；不扩展成全部硬件、厂商或语音组合的兼容性结论。

## 按已安装阶段看开销

| 组件 | 运行位置与主要开销 |
|---|---|
| 游戏与 AIChat | 游戏使用 GPU；AIChat 处理界面、字幕、录音和播放 |
| SPP 与内置关键词回忆 | 本机 CPU／内存、存档与文件；文字聊天和回忆不需要 Python |
| 云端聊天模型 | 模型在服务端运行，产生 API 用量；玩家显存不加载这个云端模型 |
| 可选 E5 int8 ONNX 回忆 | 本机 CPU／内存，使用随组件提供的 ORT；不使用旧 Python Embedding worker |
| GPT-SoVITS | 按实际环境使用 GPU 或 CPU；权重与推理缓存另占资源 |
| Fun-ASR | 按实际 Python／Torch 环境与脚本的设备选择运行；不能从 ONNX 的 CPU 配置推断 ASR 设备 |
| 桌面、浏览器等 | 会另占 GPU／内存；测整卡占用时需一起考虑 |

约 **11 MB 主程序 ZIP** 和 **94 MB 模型 ZIP** 是压缩下载大小，不是内存上限。模型解压、tokenizer、运行库、向量缓存、关键词索引、存档重放，以及语音环境都会增加磁盘或内存需求。各阶段不依赖后续阶段；ONNX 可跳过，也不是 TTS／ASR 的前置条件。

## 本次本地资源测量

以下来自 CP23 D 的合成存档生命周期验证。采用 **20 ms working-set 采样**，观察 SPP 主进程加真实 ONNX worker；不是所有电脑的上限，也不包含游戏或外装 TTS／ASR。

| 指标 | 1 万条合成记录 | 5 万条合成记录 |
|---|---:|---:|
| 真实格式 WAL 大小／帧数 | 81.62 MB／100,314 帧 | 409.89 MB／501,564 帧 |
| 启动重放与档案投影 | 11.65 秒 | **495.12 秒（约 8 分 15 秒）** |
| 首次关键词构建 | 73.58 ms | 439.82 ms |
| 暖关键词查询平均 | 10.94 ms | 87.62 ms |
| 权威复核＋关键词＋真实语义查询平均 | 23.37 ms | 140.22 ms |
| 整管线采样观察峰值 | 440,557,568 B | **943,693,824 B（约 944 MB）** |
| 暖混合查询阶段观察峰值 | 343,506,944 B | 735,981,568 B |

另一个 **350 MB 门禁仅针对真实 int8 worker＋5 万向量持续查询**，第二轮最大 **332,283,904 B**。该门禁不含存档、关键词索引、WAL 或启动，**不能写成整套 SPP ≤350 MB**。

大 WAL 冷启动仍慢；本次没有设定并通过冷启动速度门禁。合成 WAL 使用真实格式和 hash 链重放，但不代表 5 万回合都经过真实云端调用／live commit；生命周期缓存使用合成向量，不代表所有记录都推理过 E5。真实模型的加载与查询另外验证。实际玩家文本、硬件与历史规模会改变耗时和内存；来源与范围见[维护记录](MAINTAINER_STATUS.zh-CN.md)。

## GPU 语音与非 NVIDIA 设备

沿用此前工程参考：游戏、GPT-SoVITS 和 Fun-ASR 同时使用本机 GPU 时，8 GB 显存可作为评估起点，12 GB 或以上通常更有余量。**这是容量参考，不是已经测得的最低配置或兼容保证。** 大分辨率、多显示器、声线版本、精度和重复服务都会改变需求；显存容量也不能代替驱动、算子与依赖兼容性。

| 环境 | 安装顺序与验证边界 |
|---|---|
| NVIDIA 与匹配 CUDA 环境 | 先完成文字，再分别加载／测试 TTS 与 ASR，记录整卡峰值 |
| AMD、Intel、集成显卡 | 可先使用文字和 ONNX CPU 回忆；语音需要合适的 CPU 环境或已适配后端 |
| ASR CPU＋TTS GPU | 可减少 ASR GPU 负担，但增加 CPU／内存和等待时间；需实际 F8 与持续通话验证 |
| 全 CPU 语音 | 按上游支持环境配置并试听／识别；不能保证实时体验 |

本项目没有新增覆盖全部 AMD／Intel Windows GPU 后端的验证。不能直接使用 NVIDIA CUDA 包，也不能只换未经支持的设备字符串。GPT-SoVITS CPU 路线需同时核对 `device: cpu`、`is_half: false`；Fun-ASR 当前随包脚本的 `AutoModel` 没有显式 CPU 参数，CPU 副本方法见[语音进阶配置](VOICE_SETUP.zh-CN.md#asr-cpu)。[PyTorch 安装选择器](https://pytorch.org/get-started/locally/)和所用整合包的说明决定实际可安装环境。

## 测量和降低重复占用

1. 在任务管理器“详细信息”中添加“命令行”列，确认每个进程。GPT-SoVITS 常为 `api_v2.py`，Fun-ASR 为 `satone_funasr_server_v1.py`，本版本语义 worker 是 SPP 原生子进程，不是 `embedding_worker.py`。
2. 只保留所需服务；用 API 合成时关闭不需要的另一份 WebUI 推理实例。关闭持续通话或网页标签不代表模型进程已退出。
3. 分别测桌面、仅游戏、加入 TTS、加入 ASR、加入语义查询的整卡和内存峰值，并记录模型、设备、精度、分辨率与响应延迟。
4. 设备与模型支持时再尝试更轻权重或精度调整；改动后重新生成可播放音频、识别短句和较长录音。

此前 2026-09-27 截图有两个 Python 进程的专用 GPU 内存约 2.17／1.92 GiB，游戏约 0.63 GiB，但没有完整进程身份、模型、精度与阶段，不能当作固定 TTS／ASR 占用。跨进程共享 GPU 资源可能重复计数，整卡读数应查看“性能 → GPU → 专用 GPU 内存”；统计说明见 [Microsoft：GPUs in the task manager](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/)。不要结束 Windows 桌面进程来“节省 Mod 显存”。
