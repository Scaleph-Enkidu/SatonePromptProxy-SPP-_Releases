# 使用資源とハードウェアの制約

[ホーム](README.md) · [導入](INSTALL.md) · [音声](VOICE_SETUP.md)

現在の組み合わせは AIChat 1.18.28 + SPP 5.10.8 です。以下の測定は元の日付と範囲のままで、文書更新によって新しい機器検証を行ったことにはなりません。

## VRAM の観測値

**GPU で動かす GPT-SoVITS と Fun-ASR には、ゲーム・デスクトップに加えて数 GB の VRAM が必要です。** 2026-09-27 の画面記録では次の値でした。

| プロセス | 専用 GPU メモリ | 範囲 |
| --- | ---: | --- |
| Python 1 | 約 2.17 GiB | コマンドライン未記録のため TTS／ASR／別インスタンスの識別不可 |
| Python 2 | 約 1.92 GiB | 同上 |
| ゲーム | 約 0.63 GiB | その場面の値で、全場面の最大値ではない |

固定の必要容量ではなく観測値です。モデル、精度、機器、処理段階は十分に記録されていません。GiB は 1024³、GB は 1000³ バイトです。下記の RAM とは別の資源です。共有 GPU 資源は複数プロセスに重複計上され得るため、**3 つを足してカード全体の使用量にはしません**。タスクマネージャー → パフォーマンス → GPU → 専用 GPU メモリで全体を確認します。[Microsoft の説明](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/)と[当時の記録](https://github.com/Scaleph-Enkidu/SatonePromptProxy-SPP-_Releases/blob/63925a2ede595ac852b8d69a8572dcd64cfa6372/README.md)も参照してください。

**GPU 音声一式の検討開始点を 8 GB、余裕を持たせるなら 12 GB 以上**とします。GPU・声の組み合わせ全体で確認した最低要件ではなく、別途ローカル会話 LLM を動かす分も含みません。

| VRAM／用途 | 検討できる構成 |
| --- | --- |
| 12 GB 以上 | ゲーム、TTS、ASR、ピーク用の余裕。選ぶモデル・解像度で実測する |
| 8 GB | GPU 音声一式の検討開始点。重複サービスを止めてカード全体を測る |
| 6 GB | GPU TTS＋CPU ASR を試し、F8・連続会話・遅延を確認 |
| 4 GB 以下／内蔵 GPU | まず文字。音声は対応する CPU 環境を別途検証 |
| 文字＋クラウド API | クラウド会話モデルの重みはローカル VRAM に載らず、TTS／ASR は省略可能 |

容量だけでバックエンド互換性は決まりません。AMD・Intel の Windows GPU 音声経路は全面検証されておらず、NVIDIA CUDA 手順をそのまま使えません。**検証済みの統一低 VRAM モードはなく、報告されたゲームのフレーム低下も原因未解決です。**

## 構成要素と容量

ゲームは GPU を使い、AIChat は UI・字幕・録音・再生を扱います。SPP とキーワード検索は Python なしで CPU・RAM・ファイルを使います。任意の E5 int8 は付属 ORT による CPU 処理です。GPT-SoVITS と Fun-ASR は各環境・スクリプトの指定機器を使い、ONNX の CPU 設定が ASR を CPU にするわけではありません。ブラウザーやデスクトップも資源を使います。

現在の三言語 ZIP は約 43 MB（元 N15 は約 39 MB）、以前の 1.17.x は約 11 MB、任意モデルは約 94 MB です。**ダウンロード容量は RAM 上限ではありません。** 展開、tokenizer、ライブラリ、ベクトル、キーワード索引、WAL 再生、音声環境でディスク・メモリが増えます。後段は任意で、発声に ONNX は必須ではありません。

## RAM と起動時間：過去の CP23 D 測定

合成データのライフサイクル測定で、**SPP 親プロセス＋実 ONNX worker を 20 ms 間隔で working-set 計測**しました。VRAM ではなく RAM で、ゲーム・外部 TTS／ASR は含まず、全 PC の最大値でもありません。MB は十進数です。

| 指標 | 合成 10,000 件 | 合成 50,000 件 |
| --- | ---: | ---: |
| 実形式 WAL 容量／フレーム | 81.62 MB／100,314 | 409.89 MB／501,564 |
| 起動時再生・アーカイブ投影 | 11.65 秒 | **495.12 秒（約 8 分 15 秒）** |
| 初回キーワード構築 | 73.58 ms | 439.82 ms |
| 準備後キーワード検索平均 | 10.94 ms | 87.62 ms |
| 正本照合＋キーワード＋実意味検索平均 | 23.37 ms | 140.22 ms |
| 全処理の観測ピーク | 440,557,568 B（約 441 MB） | **943,693,824 B（約 944 MB）** |
| 準備後の混合検索ピーク | 343,506,944 B | 735,981,568 B |

別の **350 MB 基準は実 int8 worker＋50,000 ベクトルの継続検索のみ**で、第 2 回の最大値は **332,283,904 B** でした。保存記録、キーワード、WAL、起動処理は含みません。SPP 全体が 350 MB 以下という意味ではありません。

大きな WAL のコールドスタートは依然遅く、起動速度の合格基準を設定・通過したわけではありません。合成 WAL は実形式とハッシュ鎖を使いますが、50,000 回の実クラウド／live commit ではありません。ライフサイクル用ベクトルも合成で、全件を E5 推論したわけではありません。実モデルの読み込み・検索は別に確認しました。実際の文章、機器、履歴規模で結果は変わります。[元の保守記録（中国語）](../MAINTAINER_STATUS.zh-CN.md)に範囲を残しています。

## 機器選択と測り方

対応 CUDA の NVIDIA では文字から始め、TTS／ASR を個別に試します。AMD・Intel・内蔵 GPU は文字と CPU ONNX を先に使い、音声は適切な CPU 環境か対応バックエンドを用意します。GPU TTS＋CPU ASR は ASR の GPU 負担を減らしますが、CPU・RAM・遅延が増えます。全 CPU 音声はリアルタイム性を保証しません。

GPT-SoVITS の CPU 設定は `device: cpu` と `is_half: false` の両方が必要です。付属 Fun-ASR の `AutoModel` に明示的 CPU 指定はないため、[CPU 用コピー](INSTALL.md#asr-cpu)を使います。未対応の機器名に変えるだけでは動きません。[PyTorch 選択画面](https://pytorch.org/get-started/locally/)で実際の対応環境を確認してください。

1. タスクマネージャーの詳細にコマンドライン列を追加します。TTS は通常 `api_v2.py`、ASR は `satone_funasr_server_v1.py`、意味検索は SPP のネイティブ子プロセスで `embedding_worker.py` ではありません。
2. 必要なインスタンスだけを残します。API 利用時に不要な WebUI 推論を閉じます。ブラウザーや連続会話を閉じてもモデルプロセスは終了しない場合があります。
3. デスクトップ、ゲームのみ、TTS 追加、ASR 追加、意味検索を別々に測ります。全カード・RAM のピーク、モデル、機器、精度、解像度、遅延を記録します。
4. 対応する場合だけ軽い重み・精度を試し、再生可能な音声と短文・長めの認識を再確認します。

専用 VRAM、共有 GPU メモリ、RAM を区別し、全カードの画面とコマンドラインを残します。節約のために Windows のデスクトッププロセスを終了しないでください。
