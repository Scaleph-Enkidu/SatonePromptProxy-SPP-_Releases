# 過去の会話の検索

[システムの説明一覧](../README.md#systems) · AIChat 1.18.28 + SPP 5.10.8

検索は、現在のプロファイルから関連する交流を選び、必要に応じて会話モデルに渡します。毎回すべての過去ログを読ませる仕組みではありません。

| 方法 | 動作 | 導入条件 |
| --- | --- | --- |
| キーワード検索 | 文字列、キーワード、中国語・日本語の断片で探す | 内蔵。文字チャットに Python は不要 |
| 意味検索 | ローカルのベクトルモデルで意味を比較し、言い換えにも対応 | 約 94 MB の任意 ONNX コンポーネントを導入して有効化。CPU で動作 |

例えば「前に話した楽器の練習はどう？」から「最近ピアノを練習している」という記録を探せる場合があります。ただし結果は記録、言い回し、モデル、絞り込み条件に左右されます。

## 対象となる履歴

キーワード索引は利用できる履歴全体を対象にします。意味検索用の投影は**最新 50,000 件の交流済み記録**までです。それより古い記録も正本に残り、キーワード検索できます。記憶削除の上限でも、画面の 50 発言表示制限でもありません。

索引はプロファイルごとに作成・検索し、他のプロファイルの経験を混ぜません。現在の提示追跡経路では、実際に表示した文字と再生完了した音声区間を確認し、未提示の候補を交流済みとして扱いません。

## 見つかっても返答に出ない理由

スコア、意味検索の優位性、元記録の照合によって、今回の文脈に入れるかを決めます。類似度は事実の正しさの確率ではありません。似ていても異なる経験を混同しないよう慎重に選びます。

長い記録は意味モデルへの入力で切り詰められることがありますが、キーワード検索は全文を使えます。文脈に入っても、会話モデルが見落とし、誤解し、今回の返答で触れない場合があります。

## 任意コンポーネントの状態

ONNX は標準で無効です。ファイル不足、検証失敗、読み込み失敗、処理中、時間切れなどではキーワード検索に戻れるため、文字チャットのために意味検索の準備を待つ必要はありません。初回有効化やプロファイル変更時には準備・構築が必要で、`loading`、`building`、`ready` は別の状態です。

`semantic_recall_v1` は手順に従って再構築できるキャッシュですが、私的な会話由来の情報を含むので保護してください。自由に消してはいけない正本 `local_v1` とは異なります。[ONNX 設定](../ONNX_SETUP.md)と[大規模履歴の測定](../HARDWARE.md)を参照してください。
