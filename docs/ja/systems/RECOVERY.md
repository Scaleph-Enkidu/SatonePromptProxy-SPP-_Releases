# 返答の検証と障害復旧

[システムの説明一覧](../README.md#systems) · AIChat 1.18.30 + SPP 5.10.10

「モデルが生成した内容」「プログラムが受理した内容」「相手が実際に見た・聞いた内容」を区別します。形式不正、通信断、再生中断が記憶・関係・質問の重複判定に与える影響を減らすためです。

## 形式検証

返答には有効な感情タグ、音声・字幕用の項目、区間ごとの長さ制限が必要です。項目不足、不正タグ、長さ超過、サービスからの不完全な返答を、そのまま字幕・音声へ流しません。回数・時間の予算内で形式修復や再生成を試せますが、失敗が続けば該当状態で終了します。無限再試行でも、事実確認や翻訳の正しさの保証でもありません。

| 提示状態 | 後続処理で使えるもの |
| --- | --- |
| 文字・音声とも完了 | 確認済み内容を文脈・記憶・関係へ使用 |
| 字幕だけ完了 | 表示確認済みの文字。音声まで完了したとしない |
| 音声だけ完了 | 再生確認済みの内容。字幕全体の表示を仮定しない |
| 一部だけ表示・再生 | 確認済みの部分だけを使い、未完了状態を保持 |
| 未提示・記録遅延・確認不能 | 候補全体を受領済みの返答にしない |

候補が診断・復旧記録に残っていても、完全な共有体験として次回に渡されたことにはなりません。旧版からの取り込みや提示追跡のない互換経路は、それぞれ従来の処理に従います。すべての古い記録を遡って再判定するわけではありません。

## 通信断と重複要求

ローカル記録に要求・バックグラウンド処理の進捗を残し、再接続・再起動時に分かっている状態から復旧します。同じ報酬、減点、記憶書き込みを二重適用しないための仕組みで、結果不明を成功扱いにはしません。

リモートモデルが完了していても、中断前に結果を確実に保存できなかった場合は再呼び出しが必要になることがあります。**ローカルの二重適用防止は、リモート呼び出しが 1 回だけになる保証ではありません。** 失敗・キャンセル・復旧でも API 使用量が発生し得ます。

確認待ち・保留入力の表示では状態を確認し、画面の復旧操作を使ってください。警告を消すために `local_v1`、プロファイル全体、認証情報を削除しないでください。バージョン、時刻、入力方法、実際の表示・音声、UI 状態、伏せ字処理したログを記録します。認識失敗、モデル失敗、合成失敗、再生中断を区別してください。[サービス](SERVICES.md)と[プライバシー](../DATA_AND_PRIVACY.md)も参照してください。
