# 音声入力と連続会話

[システムの説明一覧](../README.md#systems) · AIChat 1.18.28 + SPP 5.10.8

マイクで録音した声を Fun-ASR が文字に変換し、その文字を会話モデルへ送ります。ASR はプレイヤーの認識、TTS は聡音の発声で、別々に導入できます。

| モード | 操作 | 用途 |
| --- | --- | --- |
| 押して話す | F8 を押して録音し、離すと送信。画面ボタンも利用可能 | 録音範囲を自分で決め、まず短い認識を試す |
| 連続会話 | 選択したマイクで待ち受け、VAD で発言を区切る | 毎回キーを押さずに話す |

両者は同じ選択済みマイクを使います。未導入、無効、読み込み中、準備完了は異なる状態です。ストーリーや通信断による制限も適用されます。

## 検出と先頭バッファー

VAD は発話の開始と終了を判断します。しきい値が高すぎると小声を逃し、低すぎるとファン・キーボード・背景音を声と判断します。停止時間の設定は送信タイミングに影響します。検出前の短い音声を保持する先頭バッファーで、話し始めの欠落を減らします。ただしモデルの認識誤りを直すものではなく、全機器で正しく区切れる保証もありません。

## 待ち行列と停止

録音済みで未完了の入力は、セッション、プロファイル、処理状態ごとに管理します。待ち行列が満杯、保存失敗、旧入力の確認待ちなどでは、既存録音を守るために待ち受けを止めることがあります。通話を止めても待機入力がすべて消えるとは限らず、サーバーが未受信とも限りません。保留入力は[復旧手順](../INSTALL.md#preserved-voice)で 1 件ずつ処理します。

再生を中断した場合、後の記憶・関係には確認できた交流だけを使い、聞いていない返答全体を含めません。

## 原因の切り分け

1. F8 で短く話し、マイク入力と妥当な文字起こしを確認します。
2. 先頭が欠ける場合は原音保存やマイクテストで、録音時点で欠けていないか確認します。
3. 原音が完全なら、モデル、雑音、ホットワード対応を確認します。ホットワードでも正解は保証されません。
4. F8 が動いてから連続会話を調整し、1 項目ずつ保存・適用します。

無音・発話の各 10 秒テストはローカル保存のみで ASR に送りません。「次の押して話す録音を保存」は通常の認識も行います。[音声診断](../VOICE_SETUP.md#asr-troubleshooting)を参照してください。
