# 运行开销与硬件边界

[返回首页](README.md) · [四阶段安装](INSTALL.md) · [语音设置](VOICE_SETUP.md)

适用配对：**AIChat 1.18.30 + SPP 5.10.10**，更新日期 **2026-10-01**。原版本的用户实机反馈与本版自动化验证分别记录；不扩展成全部硬件、厂商或语音组合的兼容性结论。

## 显存：已有读数与安装容量参考

**完整本地语音需要为 GPT-SoVITS 与 Fun-ASR 额外预留数 GB 显存，同时还要运行游戏和桌面。** 目前能够引用的 GPU 数字来自 **2026-09-27 的一次运行截图**，已在当时的[首页硬件说明](https://github.com/Scaleph-Enkidu/SatonePromptProxy-SPP-_Releases/blob/63925a2ede595ac852b8d69a8572dcd64cfa6372/README.md)记录：

| 截图中的进程 | 专用 GPU 内存读数 | 记录范围 |
| --- | ---: | --- |
| Python 进程一 | **约 2.17 GiB** | 未记录命令行，不能确认是 TTS、ASR 或其他实例 |
| Python 进程二 | **约 1.92 GiB** | 同上，不能仅按占用大小判断服务身份 |
| 游戏进程 | **约 0.63 GiB** | 该次游戏画面的读数，不是所有场景的峰值 |

**这些数字回答的是“当时看到了多少占用”，不是每个组件的固定需求。** 截图缺少完整模型、精度、设备与阶段，尚不能给出可靠的“TTS 固定多少 GB／ASR 固定多少 GB”或整套语音峰值。GiB 按 1024³ 字节计算，GB 按 1000³ 字节计算；下方 SPP 的 MB 数据是系统内存，两者不能混用。

跨进程共享的 GPU 资源可能在多个进程中重复计数，**不把 2.17、1.92 和 0.63 GiB 相加当作整卡占用**。核对整卡专用显存应看任务管理器“性能 → GPU → 专用 GPU 内存”；这是 [Microsoft 官方统计说明](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/)给出的统计口径。

沿用此前的工程参考：**8 GB 显存作为完整 GPU 语音的评估起点，12 GB 或以上更有余量。** 这不是经多档显卡和声线实测得出的最低配置；还需预留桌面、其他程序及推理峰值，不包括另行部署本地聊天大模型。

| 显存规格／使用方式 | 容量参考与可选路线 |
| --- | --- |
| 12 GB 或以上 | 为游戏、TTS、ASR 及峰值预留更多余量，仍需测所选模型与分辨率 |
| 8 GB | 完整 GPU 语音的评估起点；关闭重复服务并观察整卡峰值 |
| 6 GB | 可尝试 TTS 使用 GPU、ASR 使用 CPU；需验证 F8、持续通话及等待时间 |
| 4 GB 或以下／集成显卡 | 优先文字聊天；语音另行选择并验证 CPU 环境，游戏本身仍有要求 |
| 文字聊天＋云端 API | 本机不加载云端聊天模型的 GPU 权重，TTS／ASR 可以不安装 |

显存容量不能代替设备兼容性。AMD／Intel 的 Windows GPU 语音后端尚未全面验证，不能直接使用 NVIDIA CUDA 包。**当前没有完成验证的统一低显存模式，玩家反馈的游戏掉帧根因也仍未确定。** 已有 CPU 路线和重复服务排查见下文。

## 按已安装阶段看开销

| 组件 | 运行位置与主要开销 |
|---|---|
| 游戏与 AIChat | 游戏使用 GPU；AIChat 处理界面、字幕、录音和播放 |
| SPP 与内置关键词回忆 | 本机 CPU／内存、存档与文件；文字聊天和回忆不需要 Python |
| 云端聊天模型 | 模型在服务端运行，产生 API 用量；玩家显存不加载这个云端模型 |
| 可选 E5 int8 ONNX 回忆 | 本机 CPU／内存，使用随组件提供的 ORT；不使用旧 Python Embedding worker |
| GPT-SoVITS | 按实际环境使用 GPU 或 CPU；权重与推理缓存另占资源 |
| Fun-ASR | 按实际 Python／Torch 环境与脚本的设备选择运行；不能从 ONNX 的 CPU 配置推断 ASR 设备 |
| 桌面、浏览器等 | 会另占 GPU／内存；测整卡占用时需一起考虑 |

当前约 **43 MB 三语文档 ZIP**（原 N15 包约 39 MB，旧 1.17.x 包约 11 MB）和 **94 MB 模型 ZIP** 是压缩下载大小，不是内存上限。模型解压、tokenizer、运行库、向量缓存、关键词索引、存档重放，以及语音环境都会增加磁盘或内存需求。各阶段不依赖后续阶段；ONNX 可跳过，也不是 TTS／ASR 的前置条件。

## 系统内存与启动耗时：本次本地资源测量

以下来自 CP23 D 的合成存档生命周期验证，测量的是 **SPP 系统内存（RAM），不是显存（VRAM）**。采用 **20 ms working-set 采样**，观察 SPP 主进程加真实 ONNX worker；不是所有电脑的上限，也不包含游戏或外装 TTS／ASR。按十进制 MB 换算，1 万条记录观察峰值约 **441 MB**，5 万条约 **944 MB**；没有整套游戏＋语音的系统内存峰值记录。

| 指标 | 1 万条合成记录 | 5 万条合成记录 |
|---|---:|---:|
| 真实格式 WAL 大小／帧数 | 81.62 MB／100,314 帧 | 409.89 MB／501,564 帧 |
| 启动重放与档案投影 | 11.65 秒 | **495.12 秒（约 8 分 15 秒）** |
| 首次关键词构建 | 73.58 ms | 439.82 ms |
| 暖关键词查询平均 | 10.94 ms | 87.62 ms |
| 权威复核＋关键词＋真实语义查询平均 | 23.37 ms | 140.22 ms |
| 整管线采样观察峰值 | 440,557,568 B | **943,693,824 B（约 944 MB）** |
| 暖混合查询阶段观察峰值 | 343,506,944 B | 735,981,568 B |

另一个 **350 MB 门禁仅针对真实 int8 worker＋5 万向量持续查询**，第二轮最大 **332,283,904 B**。该门禁不含存档、关键词索引、WAL 或启动，**不能写成整套 SPP ≤350 MB**。

大 WAL 冷启动仍慢；本次没有设定并通过冷启动速度门禁。合成 WAL 使用真实格式和 hash 链重放，但不代表 5 万回合都经过真实云端调用／live commit；生命周期缓存使用合成向量，不代表所有记录都推理过 E5。真实模型的加载与查询另外验证。实际玩家文本、硬件与历史规模会改变耗时和内存；来源与范围见[维护记录](../MAINTAINER_STATUS.zh-CN.md)。

## GPU 语音与非 NVIDIA 设备

显存读数与 4／6／8／12 GB 容量参考见本页开头。大分辨率、多显示器、声线版本、精度和重复服务都会改变需求；显存容量也不能代替驱动、算子与依赖兼容性。

| 环境 | 安装顺序与验证边界 |
|---|---|
| NVIDIA 与匹配 CUDA 环境 | 先完成文字，再分别加载／测试 TTS 与 ASR，记录整卡峰值 |
| AMD、Intel、集成显卡 | 可先使用文字和 ONNX CPU 回忆；语音需要合适的 CPU 环境或已适配后端 |
| ASR CPU＋TTS GPU | 可减少 ASR GPU 负担，但增加 CPU／内存和等待时间；需实际 F8 与持续通话验证 |
| 全 CPU 语音 | 按上游支持环境配置并试听／识别；不能保证实时体验 |

本项目没有新增覆盖全部 AMD／Intel Windows GPU 后端的验证。不能直接使用 NVIDIA CUDA 包，也不能只换未经支持的设备字符串。GPT-SoVITS CPU 路线需同时核对 `device: cpu`、`is_half: false`；Fun-ASR 当前随包脚本的 `AutoModel` 没有显式 CPU 参数，CPU 副本方法见[语音进阶配置](VOICE_SETUP.md#asr-cpu)。[PyTorch 安装选择器](https://pytorch.org/get-started/locally/)和所用整合包的说明决定实际可安装环境。

## 测量和降低重复占用

1. 在任务管理器“详细信息”中添加“命令行”列，确认每个进程。GPT-SoVITS 常为 `api_v2.py`，Fun-ASR 为 `satone_funasr_server_v1.py`，本版本语义 worker 是 SPP 原生子进程，不是 `embedding_worker.py`。
2. 只保留所需服务；用 API 合成时关闭不需要的另一份 WebUI 推理实例。关闭持续通话或网页标签不代表模型进程已退出。
3. 分别测桌面、仅游戏、加入 TTS、加入 ASR、加入语义查询的整卡和内存峰值，并记录模型、设备、精度、分辨率与响应延迟。
4. 设备与模型支持时再尝试更轻权重或精度调整；改动后重新生成可播放音频、识别短句和较长录音。

记录时区分专用显存、共享 GPU 内存与系统内存，并保留任务管理器整卡截图及进程命令行。不要结束 Windows 桌面进程来“节省 Mod 显存”。
