# 记忆与档案系统说明

[返回系统说明入口](../README.md#systems) · [历史回忆与检索](RECALL.md) · [数据保存与备份](../DATA_AND_PRIVACY.md)

适用版本：**AIChat 1.18.28 + SPP 5.10.8**。三语文档整理：2026-10-06；原测试数据仍按其记录日期理解。

聪音的记忆不是把全部聊天永远塞进同一次模型请求。系统保留本地记录，每轮选取近期交流、整理后的记忆和相关历史，组成这次交谈需要的上下文。

## 三套档案分别保存什么

记忆1、记忆2、记忆3分别保存聊天、长期记忆和 AI 关系。切换档案后使用对应档案的内容，不会把另一档案的经历直接当成当前档案的经历。

人格文件由三个档案共用，服务和模型也可以切换。同一档案从一个聊天服务切到另一个服务时，可以继续使用本地记忆与关系；新模型的语气和理解能力仍可能不同。

默认记忆3有满好感测试预设，不能把它与普通新档案的初始关系混为一谈。具体初始值见[好感度系统](AFFECTION.md)。

## 三种内容的区别

| 内容 | 怎么参与聊天 |
| --- | --- |
| 近期原文 | 保留近期实际交流，帮助延续当前话题 |
| 长期记忆摘要 | 将较早交流中重要的信息整理后继续带入上下文 |
| 完整本地记录与历史索引 | 保留旧交流，按当前话题检索，不要求每轮全部发送 |

窗口只显示最近 50 句，不代表只保存 50 句，也不代表模型每轮读取完整存档。摘要可以遗漏细节，检索也可能没有命中；“保存在本机”与“这轮模型已经知道”是两回事。

## 自动整理何时发生

默认整理策略的阈值为 **32,000 token**，近期原文保留目标约 **12,000 token**；token 是模型处理文本的计量单位，不等于中文字数。本版本地聊天还会考虑估算请求预算和近期消息数量，接近限制时可以提前整理。

这两个数值不是所有模型通用的上下文上限，也不是保证每次请求恰好只剩这些 token。人格、当前输入、长期摘要和其他上下文都占空间；不同连接的预算也会影响整理时机。

整理把较早交流压缩成摘要，同时保留原始存档。生成了但没有实际展示或播放的内容，不应作为聪音已经与你说过的话进入记忆。整理失败时保留历史，不能假装摘要已经成功；上下文仍超出预算时，这轮请求可能无法继续。

## 保存与升级

本版本地聊天的权威记录在 `local_v1` 中，档案数据保存在 `memory_profiles` 等目录；旧安装可能还保留旧版 JSON、文本和数据库。不能只看某个旧文件没有更新，就判断所有新聊天都没有保存。

退出游戏和相关服务后，备份整个 SPP 个人运行目录及游戏端配置、历史文件。不要把权威记录当作可清理缓存；具体路径、备份和回退方式见[数据保存、备份与隐私](../DATA_AND_PRIVACY.md)。
