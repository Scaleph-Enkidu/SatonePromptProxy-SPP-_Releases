# 回复校验与失败恢复说明

[返回系统说明入口](../README.md#systems) · [记忆与档案](MEMORY.md) · [边界与关系修复](BOUNDARIES.md)

适用版本：**AIChat 1.18.30 + SPP 5.10.10**。三语文档整理：2026-10-06；原测试数据仍按其记录日期理解。

系统区分“模型生成了什么”“程序接受了什么”以及“实际向玩家展示或播放了什么”。这能减少格式错误、断线和播放中断对后续记忆、关系与重复提问判断的影响。

## 为什么要检查回复

聪音的回复需要包含有效情绪、日语和中文字幕，并满足分段限制。字段缺失、标签无效、长度超限或服务返回不完整内容时，不能直接把原始输出交给字幕和语音链路。

程序可以在次数与时间预算内尝试格式修复，必要时进行有界重新生成；持续失败时结束失败流程或显示对应提示。不会无限重试，也不能把格式修复当作事实核查或正确翻译保证。

## “已经生成”不等于“已经交流”

| 情况 | 后续处理原则 |
| --- | --- |
| 文字和语音完整呈现 | 使用已确认内容参与后续上下文、记忆和关系 |
| 只有中文字幕完整展示 | 可确认展示的中文参与交流，不凭空补成日语已经播放 |
| 只有日语音频完成 | 按可确认的播放内容处理，不假设所有中文字幕已经出现 |
| 只展示或播放部分片段 | 使用可确认的部分，保留未完成状态 |
| 未呈现、记录晚到或无法确认 | 不能直接把完整候选答案视为玩家已经收到 |

原始候选可能仍保留在本地诊断与恢复记录中，这不等于它被作为完整共同经历送进下一次聊天。旧版导入记录和没有新呈现追踪的兼容路径有各自的历史处理，不能套用为对所有旧记录的重新认定。

## 断线、重启与重复提交

本地记录保存请求与后台任务进度，重连或重启后按已知状态恢复，尽量避免同一次奖励、关系扣分或记忆写入重复应用。结果未知时不能直接假装成功。

远端模型已经完成请求、但本地尚未可靠记录结果时，如果进程中断，可能需要再次调用模型。**本地避免重复应用，不等于远端保证只调用一次。** 失败、取消或恢复也可能已经产生 API 用量。

出现“待确认”“保留输入”或无法继续的提示时，先看当前状态，再使用界面提供的恢复处理。不要为消除提示而删除 `local_v1`、整个档案或凭据文件。

## 遇到问题需要记录什么

保留配对版本、发生时间、输入方式、是否已看到文字／听到声音、界面状态和脱敏日志。要区分 ASR 没有识别、模型回复失败、TTS 合成失败和播放中断，不能都归为“聪音没听清”。

具体服务检查见[服务管理](SERVICES.md)，日志与隐私范围见[数据说明](../DATA_AND_PRIVACY.md)。
